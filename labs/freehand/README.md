# Freehand Lab — 手で自由に作ったら、どこまで行けるか

**モード: 探索(要件抽出)。UIを持たないラボ**([labs/README.md](../README.md) の分類では Motion / Workflow / Generative と並ぶが、画面を持たない点で [labs/event/](../event/) と同じ形)。

## 何をするラボか

**いまの出力は動画になっていない。** 直すのはそこだけで、ほかは何も変えない。

| 変えないもの | 変えるもの |
| --- | --- |
| ナレーションの言葉・BGM・メッセージ・シーンの順序・構成 | **デザイン・アニメーション・素材の使い方** |

現状の評価(2026-08-17・依頼者の言葉):

> 全てのシーンが全くビデオの体を成していない。ナレーションで言っている言葉を、白いテキストで、しかもバランス悪く画面に流し込んでいるだけ。クリエイティビティがゼロ。素人以下。
>
> 適切な素材やイメージを伝えられていない。

だから測っているのは「テンプレートに機能が足りているか」ではない。**同じ言葉・同じ構成のまま、ちゃんとデザインされ、ちゃんと動く映像**を先に1本作り、それをテンプレート側へどう持ち帰るかを、**現物を見てから**決める。

> **持ち帰り方をここに先回りして書かない。** 差分を「部品に足す/ブリーフに足す/持ち帰らない」のような分類にあらかじめ割り振る書き方が最初この位置にあったが、それは**問題が構造や項目の不足である**という前提に立っていて、実際の問題(デザインとアニメーションと素材の扱い)を外していた。**先に作る。分類は現物から。**

## 進め方

### 1. 素の書き出しをコミットする(基準線を固定する)

動画詳細の「プロジェクトデータを出力」で書き出し、`labs/freehand/<slug>/` へ展開して**編集する前にコミットする**。これをやらないと、あとから「どこまでが書き出しで、どこからが手作業か」が分からなくなる。

**あわせて、書き出した時点の logos のコミットSHAを下の表に記録する。** 書き出したソースはこのリポジトリのコピーなので、logos 側が進むと「テンプレートの上限」が動く。どの版と比べているのかを残さないと、半年後にこの diff は読めない。

### 2. 動くことを確認する

```bash
cd labs/freehand/<slug>
npm install
npm run render
```

素材(`public/`)はコミットされていないので、**書き出しZIPから展開したままの状態でだけ動く**。ここで1本出しておくと、あとで「壊したのか、元から出なかったのか」を切り分けられる。

### 3. 制約を一切気にせず、映像として成立させる

言葉と構成はそのまま、**デザインとアニメーションと素材の使い方だけを、遠慮なく作り直す**。テンプレートの語彙([remotion/kit/](../../remotion/kit/))を無視してよい。1シーンのためだけのコンポーネントを書いてよい。手でキーフレームを打ってよい。**ここで遠慮すると、比べる相手が無くなる。**

いま映像に関わっているのはこの層:

| ファイル | 何を決めているか |
| --- | --- |
| [remotion/kit/theme.ts](../../remotion/kit/theme.ts) | パレット・書体・4段の型スケール・**モーション語彙**・装飾・字幕帯 |
| [remotion/kit/layout.ts](../../remotion/kit/layout.ts) | 7つの配置・領域の幾何(`REGION_GEOMETRY`)・シーンの地 |
| [remotion/kit/components.ts](../../remotion/kit/components.ts) | 17部品と、空のときの振る舞い |
| [remotion/kit/render/](../../remotion/kit/render/) | 実際に描いているReact(`Stage` / `KitComponent` / `CaptionBand` / `motion.ts`) |
| [remotion/kit/scenes/event-cm.ts](../../remotion/kit/scenes/event-cm.ts) | 各シーンをどの部品で組むか |

### 4. できた映像を見てから、持ち帰り方を決める

**この段の手順はまだ書かない。** 何が足りなかったのかは現物が教えるはずで、先に枠を作ると枠に合う差分しか拾えなくなる。結果は各実験の `FINDINGS.md` と、下の「実験」表に書く。

## 置き場所の約束

- **ソースはコミットする。** 差分が成果物なので、コミットされていないと測定にならない
- **素材はコミットしない**([.gitignore](.gitignore))。ライセンス写真・実在人物の写真・支給BGMが入っており、git履歴に載せると取り消せない。リポジトリ直下の `/public/event/*/photos/` と同じ規則
- **logos の型チェック対象から外してある**([tsconfig.json](../../tsconfig.json) の `exclude`)。書き出したソースは logos 自身のコピーなので、外さないと**実験が logos に対して型チェックされる**(自分自身に対してではなく)。加えて、作りかけの実験が `npm run build` を落とす
- **別リポジトリにしない。** 目的が logos との差分を読むことなので、logos の文脈から離すと毎回持ち込み直すことになる
