# Freehand Lab — 手で自由に作ったら、どこまで行けるか

**モード: 探索(要件抽出)。UIを持たないラボ**([labs/README.md](../README.md) の分類では Motion / Workflow / Generative と並ぶが、画面を持たない点で [labs/event/](../event/) と同じ形)。

## 何をするラボか

**いまの出力は動画になっていない。** 直すのはそこだけで、ほかは何も変えない。

| 変えないもの | 変えるもの |
| --- | --- |
| ナレーションの言葉・BGM・メッセージ・シーンの順序・構成 | **デザイン・アニメーション・素材の使い方** |

現状の評価(2026-08-17・依頼者の言葉):

> 全てのシーンが全くビデオの体を成していない。ナレーションで言っている言葉を、白いテキストで、しかもバランス悪く画面に流し込んでいるだけ。クリエイティビティがゼロ。素人以下。
>
> 適切な素材やイメージを伝えられていない。

だから測っているのは「テンプレートに機能が足りているか」ではない。**同じ言葉・同じ構成のまま、ちゃんとデザインされ、ちゃんと動く映像**を先に1本作り、それをテンプレート側へどう持ち帰るかを、**現物を見てから**決める。

> **持ち帰り方をここに先回りして書かない。** 差分を「部品に足す/ブリーフに足す/持ち帰らない」のような分類にあらかじめ割り振る書き方が最初この位置にあったが、それは**問題が構造や項目の不足である**という前提に立っていて、実際の問題(デザインとアニメーションと素材の扱い)を外していた。**先に作る。分類は現物から。**

## 進め方

### 1. 素の書き出しをコミットする(基準線を固定する)

動画詳細の「プロジェクトデータを出力」で書き出し、`labs/freehand/<slug>/` へ展開して**編集する前にコミットする**。これをやらないと、あとから「どこまでが書き出しで、どこからが手作業か」が分からなくなる。

**あわせて、書き出した時点の logos のコミットSHAを下の表に記録する。** 書き出したソースはこのリポジトリのコピーなので、logos 側が進むと「テンプレートの上限」が動く。どの版と比べているのかを残さないと、半年後にこの diff は読めない。

### 2. 動くことを確認する

```bash
cd labs/freehand/<slug>
npm install
npm run render
```

素材(`public/`)はコミットされていないので、**書き出しZIPから展開したままの状態でだけ動く**。ここで1本出しておくと、あとで「壊したのか、元から出なかったのか」を切り分けられる。

### 3. 制約を一切気にせず、映像として成立させる

言葉と構成はそのまま、**デザインとアニメーションと素材の使い方だけを、遠慮なく作り直す**。テンプレートの語彙([remotion/kit/](../../remotion/kit/))を無視してよい。1シーンのためだけのコンポーネントを書いてよい。手でキーフレームを打ってよい。**ここで遠慮すると、比べる相手が無くなる。**

いま映像に関わっているのはこの層:

| ファイル | 何を決めているか |
| --- | --- |
| [remotion/kit/theme.ts](../../remotion/kit/theme.ts) | パレット・書体・4段の型スケール・**モーション語彙**・装飾・字幕帯 |
| [remotion/kit/layout.ts](../../remotion/kit/layout.ts) | 7つの配置・領域の幾何(`REGION_GEOMETRY`)・シーンの地 |
| [remotion/kit/components.ts](../../remotion/kit/components.ts) | 17部品と、空のときの振る舞い |
| [remotion/kit/render/](../../remotion/kit/render/) | 実際に描いているReact(`Stage` / `KitComponent` / `CaptionBand` / `motion.ts`) |
| [remotion/kit/scenes/event-cm.ts](../../remotion/kit/scenes/event-cm.ts) | 各シーンをどの部品で組むか |

### 4. できた映像を見てから、持ち帰り方を決める

結果は各実験の `FINDINGS.md` と、下の「実験」表に書く。

**sake-2026 の現物(v8)から、持ち帰り計画を確定した(2026-08-18)。** 依頼者の評価: テンプレート出力からの大幅なアップデートであり、この水準なら納品に足る。動画素材が無くても**十分な画像があれば**(動かす・タイルに並べる・連作でカットする)リッチな映像体験が作れる——つまり画像をどんどん用意することが解になる。そして今回加えたものの大半は**再現可能**で、表現を**オブジェクトとして蓄積し、組み合わせを増やす**形でテンプレートへ持ち帰る。これはLP・バナーにも同じ形で効く。

## 持ち帰り計画(次のセッションの実行順)

**原則: 並行システムを作らない。** kit([remotion/kit/](../../remotion/kit/))は既に「部品17+配置7+テーマ」のオブジェクト体系なので、持ち帰りとは**kitの語彙を増やすこと**。freehand側のコードは正本にせず、証拠(FINDINGS)と実装の参照元として残す。

### Phase A — 素材と測定(kitに触らない。asset-normalization §7の続き)— A1 ✅(2026-08-19)

1. ✅ **ロゴ正規化のプロダクト化**(2026-08-19 実装済み。正本は [docs/asset-normalization.md §11.1](../../docs/asset-normalization.md)・migration 0055)。[normalize-marks.mjs](scripts/normalize-marks.mjs) の3操作——白地プレート剥がし(`plate:"white"`=白からの距離をアルファに)・アルファboxトリム・**インク面積スケール**——を取り込み時の測定にする。`brand_materials` の測定列(`opaque`/`luminance` と同じ場所)に `ink_ratio` / `trim_width` / `trim_height` を足し、トリム済み派生物を `derived_from_material_id` で持つ([docs/asset-normalization.md](../../docs/asset-normalization.md) **段階7の実装そのもの**)。ユーザーは雑な素材を渡してくる——Miss SAKEの白枠webpがその実例で、依頼者も「アップロード時に自動で正規化される仕組みが要る」と明言した。**移植はラボの判定値を再現した**(`ink_ratio` 0.2230 / ラボ 0.2231、`scale` 0.716 / 0.725)ので、このマニフェストは以後の基準線として [lib/materials/optical.test.ts](../../lib/materials/optical.test.ts) に固定してある。**`aspect` は列にしなかった**——`trim_width / trim_height` そのものなので、保存すると計算元と食い違う
2. **SFXをシステム既定素材に**(依頼者指示: 最初から導入する)。**保管は完了(2026-08-18)**: 出自は**効果音ラボ**(商用利用無料・クレジット不要・**ただしファイル再配布は不可**)と判明し——支給10個の実測dBが同サイトのファイルと完全一致——演出用50個を [scripts/fetch-default-sfx.mjs](../../scripts/fetch-default-sfx.mjs) で取得する形にした(BGM既定と同じくmp3はgitignore、`public/defaults/sfx/catalog.json` に台帳=ラベル・出典URL・実測`headDb`→`gain`)。**残り**: `lib/assets/defaults.ts` への `kind:"sfx"` 追加とテンプレートからの参照、そして**gitignoreされた既定素材はVercelに乗らない問題**(BGMも同じ)の配備先決定
3. **「人物が写っているか」を素材の測定に足す**。人物入り写真は背景スロットに使えない(v1で実証: coverでは顔を画角外に追い出せない)。`place-images.ts` が顔の根拠で登壇者写真を選ぶのと対称の判定を、背景適性にも

### Phase C — ブリーフとパイプライン

9. **素材スロットの連作対応**。1スロット=1素材を、1スロット=Nショット(順序つき)に。`take_inputs` は既に複数行を持てるので、契約はbrief側のスロット型
10. **不足素材の生成プロンプトをテンプレートが吐く**。[ASSET-PROMPTS.md](sake-2026/ASSET-PROMPTS.md) で人手でやったこと——スロットごとの要件(16:9・**片側の暗部**・文字なし・顔なし・**セット内で照明族を固定**・器の語彙・日本酒は無色)——は全部テンプレートが知っている。「素材が無い」を「このプロンプトで作って/探して」に変えるのは、捏造の方針(空欄を見せない)の素材版
11. **LP・バナーへの水平展開**。方向性スクリム・型スケール・印章numeral・ロゴのインク面積揃えはCSSでも同じ表現。kitとLPテンプレートの共有語彙はこの計画の後(まず動画で形にする)
12. **素材の配役の自動化 — 唯一「持ち帰りきれない」もの**。freehand v8 で人間(エージェント)が手でやったことのうち、A〜Bで機械化されないのは**配役**だけ: どの素材をどのスロットへ、どのクロップ(focus)で、文字をどちら側に置くか、連作の順序をどう組むか。これは `place-images.ts`(顔の根拠で登壇者写真を選ぶ)の拡張として実装できる——**測定**(A3の人物有無+暗部がどちら側か=輝度の左右差+被写体の位置)を決定論で出し、**判断**(このイベントにこの絵は合うか)だけLLMに残す。ここが埋まるまでは、テンプレートは「同じ素材があれば同じものが出る」の一歩手前(素材とスロットの対応は人が指す)で止まる

### 順序の理由

A1→A2 は独立で今すぐ着手でき、DBに触るのはA1だけ(**A1は2026-08-19に完了**・migration 0055)。B4〜B8 は `remotion/kit/` 内で完結しテンプレート契約を壊さない(既定はすべて現行の見え方で、テーマが新語彙を使ったときだけ変わる)。C9 だけがbrief契約に触るので最後。**B5の「地の語彙」が最重要**——freehandの差分の過半はここに畳み込まれる。

## 置き場所の約束

- **ソースはコミットする。** 差分が成果物なので、コミットされていないと測定にならない
- **素材はコミットしない**([.gitignore](.gitignore))。ライセンス写真・実在人物の写真・支給BGMが入っており、git履歴に載せると取り消せない。リポジトリ直下の `/public/event/*/photos/` と同じ規則
- **logos の型チェック対象から外してある**([tsconfig.json](../../tsconfig.json) の `exclude`)。書き出したソースは logos 自身のコピーなので、外さないと**実験が logos に対して型チェックされる**(自分自身に対してではなく)。加えて、作りかけの実験が `npm run build` を落とす
- **別リポジトリにしない。** 目的が logos との差分を読むことなので、logos の文脈から離すと毎回持ち込み直すことになる
