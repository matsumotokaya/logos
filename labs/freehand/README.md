# Freehand Lab — 手で自由に作ったら、どこまで行けるか

**モード: 探索(要件抽出)。UIを持たないラボ**([labs/README.md](../README.md) の分類では Motion / Workflow / Generative と並ぶが、画面を持たない点で [labs/event/](../event/) と同じ形)。

## 何を測るラボか

logos は動画を**テンプレート**で作る。テンプレートは再現性を買うために自由を売っていて、その取引が正しいかどうかは**自由に作った場合と比べないと分からない**。

このラボは1本の動画について、次の2つを並べて置く。

1. **書き出したプロジェクトをそのまま**(= いまのテンプレートが出せる上限)
2. **それを制約なしに手で作り込んだもの**(= 表現の上限)

**成果物は動画ではなく `git diff` の読み解き**である。1と2の差が、そのままテンプレートに足りないものの一覧になる。

> 逆向きに読まないこと。差分は「テンプレートが劣っている証拠」ではない。**再現性を捨てれば当然もっとできる**——問うているのは「その差のうち、**テンプレート化できるのはどれか**」であって、「テンプレートは手作業に勝てるか」ではない。

## 進め方

### 1. 素の書き出しをコミットする(基準線を固定する)

動画詳細の「プロジェクトデータを出力」で書き出し、`labs/freehand/<slug>/` へ展開して**編集する前にコミットする**。これをやらないと、あとから「どこまでが書き出しで、どこからが手作業か」が分からなくなる。

**あわせて、書き出した時点の logos のコミットSHAを下の表に記録する。** 書き出したソースはこのリポジトリのコピーなので、logos 側が進むと「テンプレートの上限」が動く。どの版と比べているのかを残さないと、半年後にこの diff は読めない。

### 2. 動くことを確認する

```bash
cd labs/freehand/<slug>
npm install
npm run render
```

素材(`public/`)はコミットされていないので、**書き出しZIPから展開したままの状態でだけ動く**。ここで1本出しておくと、あとで「壊したのか、元から出なかったのか」を切り分けられる。

### 3. 制約を一切気にせず作り込む

テンプレートの語彙([remotion/kit/](../../remotion/kit/))に無い部品を足してよい。シーンを増やしてよい。ブリーフに無い値を直書きしてよい。**ここで遠慮すると測定にならない。**

### 4. `git diff` を3つに仕分ける

これがこのラボの本体。差分の各項目を、次のどれかに割り当てる。

| 仕分け | 意味 | 行き先 |
| --- | --- | --- |
| **語彙に足す** | 新しい部品・配置・モーション。次の案件でも使う | [remotion/kit/components.ts](../../remotion/kit/components.ts) / [layout.ts](../../remotion/kit/layout.ts) / [theme.ts](../../remotion/kit/theme.ts) |
| **ブリーフに足す** | 表現できなかった**事実やパラメータ** | `EventCmBrief`([remotion/event-cm/types.ts](../../remotion/event-cm/types.ts)) |
| **再現しない** | この案件固有の手仕事。汎用化すると語彙が濁る | 記録だけ残す |

3つ目を正直に置けるかどうかが、このラボが機能するかどうかを決める。**全部をテンプレートへ吸い上げようとすると、テンプレートは設定の集合になって誰も使えなくなる。**

⚠️ **`brief` に足したフィールドは、どこかのシーンが読むこと。** event-cm はこの規則を破って `sideCopy` / `visuals.inkArt` / `visuals.texture` の3つを持っていた時期があり、埋めても画面が何も変わらない項目が一覧に並んでいた(経緯は [README.md](../../README.md) の event-cm 節)。

### 5. 仕分けの結果をこのファイルに書く

下の「実験」表に1行足し、判断は各実験の `FINDINGS.md` に書く。**次のテンプレート要件はここから来る。**

## 実験

| slug | 元のTake | 書き出し時の logos | 状態 | 所見 |
| --- | --- | --- | --- | --- |

**sake-2026 の基準線は照合済み**: 書き出された `src/` のうち logos に対応があるファイルは**全件バイト一致**(`Root.tsx` / `index.ts` は書き出し側が生成する起動ファイルなので対象外)。`npm install` → `npm run render` で **3255フレーム=108.5秒 / 24.1MB** のMP4が出るところまで確認した。以後この `slug` に出る差分は、すべて手で入れたもの。

## 置き場所の約束

- **ソースはコミットする。** 差分が成果物なので、コミットされていないと測定にならない
- **素材はコミットしない**([.gitignore](.gitignore))。ライセンス写真・実在人物の写真・支給BGMが入っており、git履歴に載せると取り消せない。リポジトリ直下の `/public/event/*/photos/` と同じ規則
- **logos の型チェック対象から外してある**([tsconfig.json](../../tsconfig.json) の `exclude`)。書き出したソースは logos 自身のコピーなので、外さないと**実験が logos に対して型チェックされる**(自分自身に対してではなく)。加えて、作りかけの実験が `npm run build` を落とす
- **別リポジトリにしない。** 目的が logos との差分を読むことなので、logos の文脈から離すと毎回持ち込み直すことになる
