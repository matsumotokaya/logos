# デバイスモックアップの正本と残課題

「このサービスをPCとスマホに映したもの」を描く実装は**1つだけ**である。
[render-lp.ts](../lib/campaign/render-lp.ts) の `deviceMockupHtml()`(HTML+CSS)がその正本で、
LPのヒーロー、機能セクションのビジュアル、管理画面のサムネイルがすべてこれを使う。

## なぜ1つでなければならないか

管理画面のサムネイルは [campaign-ui.tsx](../app/campaigns/campaign-ui.tsx) の
`<iframe srcDoc={html} sandbox="">` で、**LPと同一のHTML**を表示している。
`sandbox=""` はスクリプトを禁止するため、**スクリプトで描くヒーローはサムネイルでは描かれない**。

かつてLPヒーローには `model-viewer` + GLB による3D実装が併存していた。
公開LPでは3D、サムネイルではCSSモックアップが出るため、同じページが2種類のキービジュアルを持ち、
不具合(スクリーンの天地反転・スマホのめり込み・回転時の欠け)は3D側にだけ存在した。
サムネイルが正しく見えていたので、不具合が長く検出されなかった。

**ヒーローに、スクリプトが動かないと成立しない要素を再び持ち込まないこと。**
ここに置くものは、サンドボックス下のiframeでも同一に描画されなければならない。
この不変条件は [render-lp.test.ts](../lib/campaign/render-lp.test.ts) が検査する。

## 3Dデバイスモックアップの現状(Workflow Lab / Draft)

3Dは [DeviceMockupBuilder.tsx](../components/mockups/DeviceMockupBuilder.tsx) から
Workflow Labでのみ使う `web.device` placement のDraftアセットとして残っている。
本編(LP・プレゼン)へ昇格させるには、下記の残課題を解消し、**描画結果を確認した上で**行う。

### 解消済み

- **スマホがノートPCへめり込む** — `generate-device-model.mjs` でスマホを右上・手前へ移動
  (`position.set(1.98, 1.32, 1.02)`)。GLBを解析してPCの全パーツと交差しないこと、
  本体上面から0.246浮くことを確認済み。この値を下げると再びめり込む
- **回転時にデバイスが表示領域から欠ける** — カメラ距離をメートル指定から
  自動フレーミング距離に対する%指定(115〜128%)へ変更。モデル形状が変わっても余白が残る

### 未解消

- **PC・スマホのスクリーン素材が上下反転する**
  - GLBのスクリーン面UVのV座標を反転する対応を試したが、**描画結果は改善しなかった**
  - 原因はジオメトリ側ではなく、テクスチャ投入側(`createCanvasTexture` と
    `createTexture` でV軸の扱いが異なる可能性)にあると見ている
  - 次に着手するときは、上下が判別できるテクスチャ(上端に赤帯+TOP、下端に緑帯+BOTTOM)を
    当てて描画を確認しながら直すこと。UVを再び触る前にこの確認を行う

## 完了条件

- 実スクリーンショットと生成Canvasのどちらも正しい上下方向で表示される
- 初期表示と全回転角度で端末が欠けない
- スマホとPCのメッシュが交差しない(解析スクリプトで確認)
- Workflow LabでPC・スマホ・duoの3種類すべてを確認する
